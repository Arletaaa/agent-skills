# 完整示例（渐进式披露）

> 本文件存放 dev-mentor 的完整实战示例，Agent 按需读取。

## 版本演进（为什么有"模式确认门"）

- **v1 → v2**：首测修正——语言选择、补"语法速查卡"上手路径、降低情绪价值并强化规范批评（见下方示例）。
- **v3**：裁决权制度化——阻塞/建议分级、用户裁决权、去口试。
- **v4**：放宽代码底线——最小完善级、意图触发 + 改动说明。
- **v5（模式确认门）**：此前只要出现"学习动机"就会被判为进入教学状态，导致用户**只想改代码**时也被拆任务、被要求自己动手。v5 明确：**学习动机 ≠ 进入教学状态**——技能触发后先问一次模式（**A** 引导式教学 / **B** 正常开发+讲解 / **C** 纯正常开发），只有用户明确说"自己写 / 别给我代码"才算已确认（**点名调用技能不算**）；未确认一律按正常开发处理，想学只体现在"顺带讲解"上。
- **v5 另加（退出教学）**：进入 A 后，用户说"**直接帮我修改 / 别教了 / 你来写 / 帮我写完**"即**立即退出教学**切到 B——可整段代写、可补全未实现部分，铁律 1（含"最小完善级"）不再适用，不反问、不劝、不设卡。判别要点：出现"直接 / 你来 / 别教了 / 交给你"→ 退出；仅"帮我改好自己刚写的这段"→ A 内的最小完善级；拿不准按退出处理；退出后不自动回到 A。**目的：避免用户被自己开启的教学模式困住。**

## 示例：Java 猜数字游戏（2026-08-23 首测，v1 → v2）

- **练习项目**：命令行猜数字游戏（Java 21）
- **用户水平**：基础 C + Java/HTML 简单界面，独立写过很少，Java 语法生疏
- **v1 暴露的问题**（促成 v2）：
  1. 导师选错语言（选了 Python，用户背景是 C/Java）→ v2 阶段一必须问"目标语言熟练度"
  2. 语言生疏时用户"写不出来" → v2 增加"语法速查卡"上手路径
  3. **用户反馈"情绪价值过高、过于顺从、需要更规范批评"** → v2 重构导师风格与 Review 标准表
- **完整引导过程**：随机数骨架 → 猜数循环 → 猜次数统计（三段，用户独立完成，见对话记录）

### v2 标准的最终评审（示例，体现"严批评"）

| 维度 | 结论 |
|------|------|
| 正确性 | ✅ 逻辑对，边界正确（nextInt(100)+1 = 1~100 含边界） |
| 可读性 | ⚠️ 命名 `randomNum`/`userNum` → 建议 `secretNumber`/`guess`；提示语中英混用 |
| 健壮性 | ❌ 输入非数字崩溃（InputMismatchException 未处理）；无 1~100 范围校验；未用 try-with-resources 释放 Scanner |
| 规范性 | ⚠️ 全逻辑塞在 main()，魔法数 100 未提为常量 |
| 扩展性 | ⚠️ 未拆方法/类，难以复用 |

**最优先改 1 条**：处理非数字输入（或将 Scanner 换成 try-with-resources）。

### 复盘

- 用户收获：从"写不出来"到独立完成一个带循环/输入/计数的 Java 程序；认可"教编程习惯"这一点
- 用户对 skill 的意见：降低情绪价值、减少顺从、增加严谨批评 → 已重构为 v2
